# Support Policy

Thank you for using `EricksonLopez.MultiTenancy`. Below are the available support channels and resources.

---

## 1. Documentation & Guides

Before opening an issue, please check the comprehensive documentation suite:

- **[Quick Start](docs/quick-start.md):** 5-minute setup and integration tutorial.
- **[Architecture Guide](docs/architecture.md):** Complete 4-layer defense-in-depth model and design decisions.
- **[Cookbook](docs/cookbook.md):** 12 production-ready engineering recipes.
- **[API Reference](docs/api-reference.md):** Complete reference of all types and extension methods.
- **[Troubleshooting Guide](docs/troubleshooting.md):** Solutions for common configuration and resolution issues.
- **[Database Dialects](docs/dialects.md):** Configuration guides for PostgreSQL, SQL Server, MySQL, MariaDB, Oracle, and SQLite.
- **[Showcase Project](samples/EricksonLopez.MultiTenancy.Showcase/):** 10 runnable progressive implementation levels.

---

## 2. Community Support Channels

- **GitHub Discussions:** Ask questions, discuss architecture patterns, share use cases, or propose ideas at [GitHub Discussions](https://github.com/ericksonlopezf/dotnet-multitenancy/discussions).
- **GitHub Issues:** Report bugs, unexpected behavior, or submit feature requests using the provided issue templates at [GitHub Issues](https://github.com/ericksonlopezf/dotnet-multitenancy/issues).

---

## 3. Bug Reports and Feature Requests

- **Bug Reports:** When submitting a bug report, provide a minimal reproduction project or unit test demonstrating the issue, along with target runtime and database dialect.
- **Feature Requests:** Open a discussion or feature request issue explaining the problem statement, proposed API, and architectural tradeoffs.

---

## 4. Security Issues

For security vulnerabilities or potential data leakage risks, do **not** use public issues. Follow the responsible disclosure process outlined in our [Security Policy](SECURITY.md).
